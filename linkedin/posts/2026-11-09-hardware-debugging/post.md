# What fixing hardware taught me about debugging code

- **Date:** Mon 9 Nov 2026, 9:00 AM IST
- **Format:** Text
- **Status:** Ready


## Caption

```
Before I wrote code for a living, I fixed computers for two years.

Turns out a broken laptop and a broken web app have a lot in common.

5 habits I brought with me:

1. Reproduce it first
If you can't make the problem happen, you can't prove you fixed it.

2. Check the simple things
Is it plugged in? In software: is the config right? Is the connection string pointing to the right database?

3. Change one thing at a time
Swap the RAM and the power supply together, and you'll never know which one was broken. Same with code.

4. Compare with something that works
Technicians swap in a known-good part. Developers compare with a working environment or the last good commit.

5. Write down what you tried
Saves hours when the same problem comes back in three months.

Debugging is less about genius and more about being patient and methodical.

What's your first step when something breaks?
```
