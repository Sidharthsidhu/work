REST API design

8-point checklist
before you ship an API

Run through it on your next endpoint.
API
1

Nouns in the URL, not verbs

The HTTP method is the verb.

GET /api/ordersGET /api/getOrders
2

Methods mean something

GET reads, POST creates, PUT replaces, PATCH updates, DELETE removes.

DELETE /api/orders/42POST /api/deleteOrder
3

Return the right status code

Not 200 for everything, errors included.

404 Not Found200 { "error": "not found" }
4

Plural, consistent names

Pick one style and keep it everywhere.

/api/customers/7/orders/api/Customer/7/order_list
5

Version it from day one

Change v2 without breaking v1 clients.

/api/v1/orders
6

Paginate lists

Never return 50,000 rows in one response.

?page=2&pageSize=20
7

One error format

Same shape every time, so clients can rely on it.

{ "message": "Invalid ID" }
8

Return DTOs, not entities

Never leak password hashes or internal fields.

OrderDtoOrder (with PasswordHash)
